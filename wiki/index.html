프로젝트 개요

Daily IT News는 매일 아침 KST 06:00에 자동 발행되는 IT 의사결정자용 정적 대시보드입니다. 어제 24시간의 뉴스·커뮤니티·오픈소스·논문을 자동 수집하고, 4기준(파급력·시의성·기술도·반응도)으로 채점하며, 20인 직책 페르소나가 종합 인사이트를 생성합니다. 서버·DB·번들러·프레임워크가 전혀 없고, file://로 열어도 그대로 동작합니다.

2 · score.js — 채점

항목마다 scoreItRelevance(IT 관련성 0~1)를 한 번만 계산해 impact 산식과 출력 shape에 재사용하고, 4기준 점수를 매긴 뒤 도메인별 shape으로 변환합니다. 마지막에 헤드라인 1건을 선정하고 뉴스 배열을 정렬합니다. 상세는 05 점수 시스템 참조.

3 · translate.js — 한글화

사용자 요구("모든 콘텐츠 한글 출력, 이후 수집 시에도 동일")로 파이프라인 필수 단계가 되었습니다. 원문은 보존하고 title_ko·summary_ko·description_ko를 추가합니다.

  • 한국어 감지 — 한글 문자 비율 > 30%면 번역 생략(이중 처리 방지)
  • 3단 사전 처리 — ① PRESERVE 정규식으로 고유명사·기술용어를 placeholder로 보호 → ② PATTERNS로 헤드라인 구문 변환("X announces Y" → "X, Y 공개") → ③ DICT 단어 치환
  • 캐시 — SHA-256 앞 24자를 키로 data/.translation-cache.json에 저장, 다음 실행에서 재사용(API 비용 절감)
  • LLM 모드 — ANTHROPIC_API_KEY가 있으면 배치 10건 단위 일괄 번역, 없으면 --no-llm 사전 fallback
⚠ 실측 품질 주의 현재 발행본에서 사전 fallback이 동작 중이며, 605건 중 224건은 한글이 전혀 없고 314건은 한·영 혼합입니다. 자세한 내용은 12 발견된 이슈 F-04.

4 · build-today.js — 조립

// 파급력 — 소스 권위 × 키워드 × 인기 보정, 마지막에 IT 관련성 승수
raw = authority(0..5) + keywordWeight×0.6 + popBoost×0.6
impact = clamp(raw × (0.4 + relevance × 0.6), 0, 5)

// 시의성 — 게시 후 경과 시간 선형 감쇠 (윈도우 안 5→1, 밖은 급감)
ratio = min(1, ageHours / windowHours)
freshness = 5 - ratio × 4        // 윈도우 초과 시 max(0, 1 - 초과비율)

// 기술도 — 기술 키워드 카운트 + 요약 길이 + 도메인 보정
depth = 2.5 + min(2, 기술키워드매칭 × 0.4)
      + (요약 200자↑ ? 0.5 : 0) + (요약 400자↑ ? 0.3 : 0)
      + (oss ? +0.5 : 0) + (community ? -0.2 : 0)

// 반응도 — points(HN score / GitHub stars) 로그 정규화
buzz = min(5, 1.5 + log10(points + 1))     // points 0이면 1.5 고정

F-12 · 유닛 테스트가 추적 중인 feed.xml을 덮어쓴다

증상
npm run test:unit을 실행하는 것만으로 저장소의 feed.xml이 수정되어 워킹 트리가 더러워집니다(이 위키를 작성하며 실제로 재현됨).
근거
generate-feed.test.js가 build()를 호출하고, build()는 상수 DEST = <repo>/feed.xml에 직접 씁니다. 게다가 인사이트 <pubDate>가 new Date()(빌드 시각)라서 내용이 바뀌지 않아도 매 실행마다 20줄이 달라집니다.
위치
scripts/generate-feed.js:24, 104, 154 · tests/unit/generate-feed.test.js
영향
발행 워크플로가 test:unit → git add feed.xml 순서라 실질 피해는 없지만, 로컬에서 테스트만 돌려도 diff가 생기고 "오늘 데이터 변경 없음" 스킵 판정이 무의미해집니다.
제안
build({ dest })로 출력 경로를 주입 가능하게 만들어 테스트는 임시 디렉터리에 쓰게 하고, 인사이트 pubDate는 D.generatedAt이나 관련 뉴스 시각으로 고정해 재현 가능한 출력을 만들기.
