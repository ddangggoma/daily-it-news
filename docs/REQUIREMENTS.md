## 1. 배경 및 목표

### 1.1 현행 시스템 요약

매일 KST 06:00에 발행되는 정적 IT 브리핑 대시보드. 125개 소스(RSS 121 + HN/Reddit/GitHub API)에서 수집 → 4기준(파급력·시의성·기술도·반응도) 휴리스틱 채점 → 한글 번역 → 20인 페르소나 인사이트 생성 → `window.__DAILY__` 단일 전역으로 직렬화 → GitHub Pages 배포. 서버·DB·번들러 없음.

강점(재개발에서도 **보존해야 할 자산**):

- 배포 전 게이트 순서(검증 → 유닛 → E2E)로 "예방에 의한 롤백" 성립
- 소스 실패 격리 구조
- IT 관련성 게이트 + 헤드라인 3중 게이트(비-IT·증권 리포트 유입 차단)
- LLM 권한 경계(시간·인기 신호는 휴리스틱이 최종 권위, 카테고리는 화이트리스트로만 수용)
- 접근성 기본기(포커스 트랩·복귀, ARIA, FOUC 제거)가 E2E로 회귀 보호됨

### 1.2 재개발 동기

현행 구조의 한계가 **데이터 계층 부재**에서 파생됩니다. 하루치 스냅샷 파일 하나가 전부이므로 이력 비교·아카이브·중복 억제·품질 추적이 불가능하고, 조용한 수집 실패가 사용자에게 그대로 노출됩니다. 실측된 대표 증상:

| ID | 증상 | 실측 |
|---|---|---|
| F-01 | 소스 다양성 미터가 US를 과대 표시 | 실제 27.4% → 표시 46% (JP 11.9%·IN 6.8% 누락분이 US로 합산) |
| F-02 | 커뮤니티 수집 붕괴 | 9건, Reddit 25개 서브레딧에서 0건, 실패가 로그에 남지 않음 |
| F-03 | 논문 탭이 arXiv 덤프 | research 885건 중 882건 arXiv, 뉴스 605건보다 많음 |
| F-04 | 번역 품질 | 605건 중 미번역 224건(37%)·한영 혼합 314건(52%), HTML 엔티티 노출 32건 |
| F-05 | 품질 지표 무의미 | 평균 4.5+ 항목 0건 → 히어로 지표·`featured` 카드 상시 0 |
| F-06 | 저장소 비대 | 30MB 번역 캐시를 매일 커밋, `.git` 139MB / 커밋 50개 |
| F-07 | 문서 드리프트 | README 10인/9카테고리/63테스트 ↔ 실제 20인/15/81 |
| F-08 | 아카이브 정지 | 7일 타임라인이 3개월 전(2026-04-25~05-01)에 고정 |
| F-09 | 인사이트 중복 | 20개 인사이트의 1순위 뉴스가 12종으로 중복, 무관한 뉴스 억지 배정 |
| F-10 | 이력 비교 미구현 | `vs7d`·`todayVs7d` 하드코딩 0, UI는 델타 위젯 노출 |
| F-11 | RSS 과다 | feed.xml 625 items / 488KB |
| F-12 | 테스트 부작용 | 유닛 테스트 실행만으로 추적 중인 `feed.xml`이 덮어써짐 |

### 1.3 제품 비전

> **"어제 IT에서 일어난 일 중, 내 직무 결정에 영향을 주는 것만 5초 안에."**

세 계층의 사용 루프를 모두 만족시킨다:

| 계층 | 시간 | 사용자가 얻는 것 |
|---|---|---|
| L1 결론 | 5초 | 헤드라인 1건 + 종합 점수 + 전일 대비 변화 |
| L2 스캔 | 1분 | 5줄 요약 + 카테고리별 상위 카드 + 오늘의 테마 |
| L3 탐색 | 10분 | 필터·검색·인사이트 모달·관련 항목·원문 이동 |

### 1.4 성공 지표 (KPI)

| ID | 지표 | 목표 |
|---|---|---|
| KPI-1 | 발행 성공률 | 30일 이동 기준 ≥ 97% (게이트로 인한 의도적 미발행은 실패로 집계하되 별도 표기) |
| KPI-2 | 헤드라인 적합률 | 수동 표본 검수 시 "IT 의사결정 관련" 판정 ≥ 95% |
| KPI-3 | 번역 완전성 | 사용자 노출 텍스트 중 한글 미번역·혼합 비율 ≤ 5% |
| KPI-4 | 수집 건전성 | 도메인(뉴스/커뮤니티/OSS/논문)별 최소 수집량 충족률 ≥ 95% |
| KPI-5 | 초기 로딩 | LCP < 2.5s (4G·중급 모바일 기준), CLS < 0.1 |
| KPI-6 | 인사이트 유효성 | 근거 항목 ≥ 2개를 인용한 인사이트 비율 100%, 페르소나 간 1순위 근거 중복률 ≤ 30% |

### 1.5 범위

**In scope** — 수집·정규화·채점·분류·번역·인사이트 생성·발행·대시보드·검색·아카이브·개인화·배포 채널(RSS/메일)·운영 관리 기능·관측성.

**Out of scope (현 단계)** — 실시간 푸시 알림, 모바일 네이티브 앱, 유료 구독/결제, 다국어 UI(한국어 단일), 원문 전문 크롤링·재배포, 소셜 로그인 기반 커뮤니티 기능.

## 2. 사용자 및 사용 시나리오

### 2.1 사용자 유형

| ID | 유형 | 설명 | 주요 관심 |
|---|---|---|---|
| U-1 | **독자 (주 사용자)** | IT 의사결정자·실무 리더. 매일 아침 5~10분 사용 | 오늘 중요한 것, 내 직무 관련성, 원문 이동 |
| U-2 | **편집자/운영자** | 소스·카테고리·페르소나 정책을 관리 | 소스 추가/차단, 페르소나 정의, 재발행, 미리보기 |
| U-3 | **개발자** | 파이프라인 유지보수 | 실패 원인 추적, 재현, 회귀 방지 |
| U-4 | **시스템(스케줄러)** | 무인 일일 실행 주체 | 결정적 실행, 실패 격리, 재시도 |
| U-5 | **구독자(수동)** | RSS 리더·메일로만 소비 | 요약 품질, 항목 수 적정성, 원문 링크 |

### 2.2 대표 시나리오

- **S-1 아침 브리핑** — 독자가 06:10 대시보드 접속 → 5초 결론 확인 → 5줄 요약 스캔 → 관심 카테고리 1개 필터 → 카드 3건 별표 → 원문 2건 새 창.
- **S-2 직무 관점 심층** — 독자가 인사이트 탭에서 자기 직무 페르소나 카드 선택 → 분석 본문의 근거 항목(뉴스·커뮤니티·OSS) 확인 → 마크다운 복사해 사내 채널 공유.
- **S-3 놓친 날 따라잡기** — 독자가 3일 부재 후 접속 → 아카이브에서 지난 3일 헤드라인 비교 → 특정 키워드로 기간 검색.
- **S-4 소스 품질 사고 대응** — 운영자가 "커뮤니티 탭이 비었다" 알림 수신 → 소스 상태 화면에서 실패 소스 확인 → 임시 비활성화 → 재수집 실행.
- **S-5 조직 맞춤** — 운영자가 자사 도메인(반도체·디스플레이)에 맞춰 페르소나 3개 추가·관심 키워드 조정 → 다음 발행부터 반영.
- **S-6 무인 실패** — 수집량 미달로 품질 게이트 실패 → 발행 중단 → 이전 발행본 유지 → 운영자에게 실패 사유 알림.

## 3. 요구사항 표기 규칙

### 3.1 ID 체계

```
FR-<영역>-<번호>    기능 요구사항        예: FR-CL-03
DR-<번호>           데이터 요구사항
EI-<번호>           외부 인터페이스 요구사항
NFR-<영역>-<번호>   비기능 요구사항
QA-<번호>           품질·검증 요구사항
CO-/AS-/OQ-<번호>   제약 / 가정 / 미결정
```

기능 영역 코드: `CL` 수집 · `NM` 정규화 · `SC` 채점 · `CT` 분류 · `TR` 번역 · `IN` 인사이트 · `PB` 발행 · `UI` 대시보드 · `SR` 검색/필터 · `AR` 아카이브 · `PS` 개인화 · `DS` 배포채널 · `AD` 운영관리 · `OB` 관측성

### 3.2 우선순위

| 표기 | 의미 |
|---|---|
| **M** (Must) | 없으면 제품이 성립하지 않음. 1차 릴리스 필수 |
| **S** (Should) | 강하게 권장. 없으면 가치가 눈에 띄게 손실 |
| **C** (Could) | 여력이 있으면 포함 |
| **W** (Won't-now) | 이번 범위에서 제외하되 설계 시 확장 여지 확보 |

### 3.3 작성 원칙

- 각 요구사항은 **검증 가능**해야 한다. "빠르게", "잘"처럼 측정 불가한 서술 금지.
- 구현 기술을 규정하지 않는다. 단, 사용자·운영에 직접 영향을 주는 제약은 9장에 명시한다.
- "근거" 열은 현행 시스템 분석에서 도출된 사유(F-xx) 또는 사용자 피드백을 가리킨다.

## 4. 기능 요구사항 (FR)

| FR-CL-01 | M | 시스템은 등록된 다수 소스에서 지정 시간 윈도우(기본 24시간, 설정 가능) 내 발행 항목을 수집해야 한다 | 윈도우 밖 항목이 수집 결과에 0건 | 현행 유지 |
| FR-CL-02 | M | 소스는 최소 4개 유형을 지원해야 한다: RSS/Atom 피드, HTTP JSON API, 소셜/커뮤니티 API, 코드 저장소 검색 API | 각 유형별 소스가 1개 이상 정상 수집 | 현행 유지 |

| FR-CL-09 | S | 일시적 실패(5xx, 타임아웃)에 대해 지수 백오프 재시도를 수행해야 한다 | 재시도 횟수·간격이 설정 가능하고 로그에 기록됨 | 신규 |

> 저장 구조·스키마 설계는 본 문서 범위 밖이며, 아래는 **보유해야 할 정보와 지켜야 할 규칙**만 규정한다.

### 5.1 보유 엔티티

| ID | 엔티티 | 필수 보유 정보 | 우선 |
|---|---|---|---|
| DR-01 | **소스(Source)** | 식별자, 표시명, 유형, 엔드포인트, 국가/지역, 도메인, 신뢰 등급, 기본 카테고리, 언어, 활성 여부, 수집 정책(상한·타임아웃) | M |
| DR-02 | **원본 수집물(RawItem)** | 소스 식별자, 수집 시각, 원본 payload, 처리 상태 | S |
| DR-03 | **항목(Item)** | 안정 식별자, 제목(원문/번역), 요약(원문/번역), 원문 URL(정규화 전/후), 소스, 발행 시각(UTC), 언어, 도메인, 카테고리(주/보조), 태그, 4기준 점수, 종합 점수, 관련성 점수, 인기 수치, 중복 군집 ID | M |
| DR-04 | **발행 스냅샷(Publication)** | 발행 일자, 생성 시각, 수집 윈도우, 헤드라인 참조, 5줄 요약, 도메인별 건수, 분포 통계, 품질 지표, 산출물 버전 | M |
| DR-05 | **페르소나(Persona)** | 식별자, 표시명, 직무 설명, 관심 도메인/키워드, 가중치, 판단 시간선, 대표 질문, 활성 여부, 소유자(기본/사용자 정의) | M |
| DR-06 | **인사이트(Insight)** | 식별자, 발행 참조, 페르소나 참조, 태그, 제목, 요약, 본문(구조화), 근거 항목 참조 목록 | M |
| DR-07 | **실행 이력(Run)** | 실행 식별자, 시작/종료 시각, 단계별 결과, 소스별 성공/실패, 게이트 판정, 오류 내역 | M |
| DR-08 | **사용자 상태(UserState)** | 별표·북마크·읽음·저장된 뷰·설정. (계정 미도입 시 클라이언트 로컬) | M |
| DR-09 | **품질 지표(Metric)** | 발행 참조, 지표명, 값, 임계, 판정 | S |
| DR-10 | **번역 캐시(TranslationCache)** | 원문 해시, 번역문, 엔진, 생성 시각, 만료 | M |
| DR-11 | **카테고리/테마 사전** | 식별자, 표시명, 아이콘, 매칭 규칙, 우선순위 | M |
| DR-12 | **감사 로그(AuditLog)** | 행위자, 시각, 대상, 변경 전/후 | S |

### 5.2 데이터 무결성 규칙

| ID | 우선 | 규칙 |
|---|---|---|
| DR-20 | M | 항목 식별자는 발행 범위 내에서 유일해야 한다 |
| DR-21 | M | 인사이트의 페르소나 참조와 근거 항목 참조는 실재해야 한다(dangling 금지) |
| DR-22 | M | 4기준 점수는 각각 0~5 범위의 유한 수여야 한다 |
| DR-23 | M | 카테고리·태그·인사이트 태그는 정의된 화이트리스트 값이어야 한다 |
| DR-24 | M | 표시용 집계값(건수·비율)은 원 데이터로부터 재계산 가능해야 하며, 저장된 집계와 재계산 결과가 일치해야 한다 |
| DR-25 | M | 비율 합계는 100%(±허용 오차)여야 하고, **누락 구간 없이** 전체를 설명해야 한다 |
| DR-26 | M | 원문 URL은 http(s) 스킴이어야 한다 |
| DR-27 | M | 발행 시각은 유효한 시각 값이어야 하며 미래 시각은 별도 처리 규칙을 따라야 한다 |
| DR-28 | S | 동일 원문에 대한 중복 항목은 군집 대표 1건으로 표현되어야 한다 |
| DR-29 | M | 발행 스냅샷은 생성 후 변경되지 않아야 한다(수정 시 새 버전) |

### 5.3 보존·용량

| ID | 우선 | 요구사항 |
|---|---|---|

## 7. 비기능 요구사항 (NFR)

### 7.1 성능 (NFR-PF)

| ID | 우선 | 요구사항 |
|---|---|---|
| NFR-PF-01 | M | 대시보드 초기 로딩 LCP < 2.5초(4G·중급 모바일), CLS < 0.1, INP < 200ms |
| NFR-PF-02 | M | 일일 수집 전체 소요 시간 ≤ 10분(소스 150개 기준). 단일 소스 지연이 전체를 지배하지 않아야 한다 |

| NFR-PF-06 | S | 과거 30일 범위 검색 응답 ≤ 1초 |

## 부록 B — 카테고리 · 소스 정책 기준

### B.1 카테고리 설계 기준 (확정은 OQ-05)

- 상호 배타적 주 카테고리 1개 + 보조 라벨 N개 구조를 권장한다(FR-CT-03).
- 광범위 catch-all 카테고리(현행 `ai`가 71% 점유)를 두지 않는다. 광의 주제는 하위 구분을 강제한다(FR-CT-02).
- 현행 15종은 출발점으로 삼되, 실측 분포를 근거로 통폐합·세분화를 검토한다.
  - 현행: AI · Dev Tools · AX · 로봇 · 디스플레이 · 디자인 · 통신 · 데이터 · 보안 · 클라우드 · 반도체 · 모바일 · 스타트업 · 논문 · 특허/표준
  - 검토 포인트: `AI` 세분화(모델/에이전트/인프라/응용), `논문`·`특허/표준`은 카테고리가 아닌 별도 도메인으로 승격 검토

### B.2 소스 편입 기준

| 기준 | 내용 |
|---|---|
| 적격성 | IT 전문 매체 또는 IT 섹션 전용 피드일 것. 종합지 전체 피드는 편입 금지(비-IT 유입 주원인) |
| 신뢰 등급 | 1차 발표(사업자·연구기관) > 전문 매체 > 애그리게이터 > 개인 채널 순으로 등급 부여 |
| 지역 균형 | 특정 지역·언어가 과점하지 않도록 도메인별 상한 운영(FR-CL-13) |
| 라이선스 | 이용약관상 요약·링크 배포가 허용될 것(NFR-LG-03) |
| 건전성 | 최근 30일 수집 성공률·유효 항목 비율이 임계 이상일 것. 미달 시 자동 비활성 검토(FR-CL-10) |

### B.3 차단 정책

- 증권 리포트·시황·공시 형태, 정치·연예·부동산·스포츠 등 비-IT 주제는 관련성 게이트와 제목 패턴으로 차단한다(FR-SC-07/08).
- 차단 규칙은 설정으로 관리하며, 차단 사유를 항목에 기록해 오탐 검토가 가능해야 한다(FR-AD-04, FR-AD-05).

## 부록 C — 수용 기준 작성 예시

요구사항 구현 시 아래 형식으로 상세 수용 기준을 작성한다.

**FR-CL-06 (소스 실패 가시화)**
```
Given 등록된 소스 120개 중 15개가 HTTP 403을 반환하는 상황에서
When  일일 수집이 실행되면
Then  나머지 105개 소스의 수집 결과는 정상 산출되고
And   실행 리포트에 실패 소스 15개의 식별자·상태코드·소요시간이 기록되며
And   운영 화면의 소스 상태 목록에서 15개가 '실패'로 표시되고
And   실패율이 임계(10%)를 초과했으므로 경보가 1건 발생한다
```

**FR-TR-03 (혼합 문장 금지)**
```
Given 영문 제목 "Xbox revenue drops 10 percent as Microsoft's cloud and AI business surges"
When  번역 엔진이 문장 전체를 번역하지 못하면
Then  화면에는 원문이 그대로 표시되고
And   해당 항목에 '미번역' 상태 배지가 표시되며
And   한국어 단어와 영어 단어가 뒤섞인 문자열은 생성되지 않는다
```

**FR-UI-05 / FR-UI-06 (집계 시각화 정확성)**
```
Given 뉴스 605건의 지역 분포가 Global 171 · US 166 · KR 85 · JP 72 · EU 41 · IN 41 · CN 29 일 때
When  소스 다양성 시각화를 렌더링하면
Then  표시된 각 지역 비율과 실제 비율의 차이가 1%p 이하이고
And   표시 항목 수를 축약한 경우 나머지는 '기타'로 합산 표시되며
And   표시된 모든 값의 합이 전체 605건을 설명한다
```

**FR-PB-10 / QA-07 (테스트 부작용 금지)**
```
Given 깨끗한 작업 트리와 운영 데이터 상태에서
When  전체 테스트 스위트를 실행하면
Then  발행 산출물·운영 데이터·버전 관리 대상 파일에 어떠한 변경도 발생하지 않는다
```
